nanochat-vlm — v3: DINOv2 Pretrained Encoder

DINOv2 ViT-B/14 6/6 correct subjects NVIDIA H200 ~147M params

Headline result
Swapping the from-scratch ViT for a DINOv2 ViT-B/14 pretrained encoder (frozen in Stage 1, gently fine-tuned at 0.1× LR in Stage 2) is a step change in quality. The v3 model correctly identifies the main subject in all 6 evaluation images, whereas the from-scratch ViT models (v1/v2) mostly hallucinated unrelated objects. It also reaches a lower validation loss at every stage (Stage 2 best: 1.81 vs v2's 2.21).

1. What changed in v3

v1 and v2 trained the ViT encoder from scratch on COCO. With only ~118k training images and a small ViT, the encoder never learned robust visual features, so the model produced fluent but wrong captions. v3 instead uses a DINOv2 ViT-B/14 backbone — 86M parameters pretrained on ~142M images (self-supervised DINO + iBOT) — which provides strong, general-purpose visual features out of the box.

The training recipe adapts to the pretrained encoder:

  • Stage 1 (projector): the DINOv2 backbone is frozen; only the 589,824-parameter linear projector (768 → 768) is trained, mapping DINOv2 patch features into the LLM's embedding space. The LLM is also frozen.
  • Stage 2 (SFT): the LLM and projector train at full LR; the DINOv2 backbone is fine-tuned at --vit-lr-scale 0.1 so its pretrained features are adapted, not destroyed.
  • Image normalization: DINOv2 expects ImageNet normalization (mean 0.485/0.456/0.406, std 0.229/0.224/0.225) instead of the unit [0,1] scaling used for the from-scratch ViT.

6. DINOv2 integration details

The DINOv2 ViT-B/14 was ported into the nanochat codebase as a new encoder option (encoder="dinov2") alongside the original from-scratch ViT. Key implementation points:

  • Architecture match: DINOv2 uses LayerNorm + GELU + a fused QKV projection + per-block LayerScale (ls1.gamma/ls2.gamma), which differs from nanochat's RMSNorm + relu² + separate QKV. A dedicated DinoViT class reproduces the DINOv2 block structure so the pretrained weights load 1:1 (175 keys, no missing/unexpected).
  • Position embeddings: DINOv2 stores pos_embed for a 37×37 grid (518px input). For 224px input (16×16 = 256 patches) it is bicubic-interpolated at load time.
  • Optimizer: the pretrained backbone is trained with AdamW (betas 0.9/0.95) rather than Muon — Muon's orthogonalization is tuned for from-scratch training and would disturb the pretrained features. torch._dynamo.config.cache_size_limit is raised to 64 because DINOv2 has ~15 distinct parameter shapes that each trigger a fused-kernel recompile.
  • Checkpointing: the encoder type is stored in the checkpoint metadata so load_vlm rebuilds the correct ViT and the CLI applies the right image normalization.

7. Reproduce

# Remote H200 — all files under /workspace/nanochat-vlm (home is not persisted)
# export NANOCHAT_BASE_DIR=/workspace/nanochat-vlm/.cache/nanochat

# 0. Data: tokenizer + d12 base (reused from v2), COCO, DINOv2 weights
python -m scripts.coco_data --split val --image-size 224
wget https://dl.fbaipublicfiles.com/dinov2/dinov2_vitb14/dinov2_vitb14_pretrain.pth \
     -O $NANOCHAT_BASE_DIR/dinov2/dinov2_vitb14_pretrain.pth

# 1. Stage 1 — projector only (DINOv2 + LLM frozen)
python -m scripts.vit_pretrain --encoder dinov2 \
  --dinov2-weights $NANOCHAT_BASE_DIR/dinov2/dinov2_vitb14_pretrain.pth \
  --normalize imagenet --model-tag vlm_d12 --max-steps 2000 \
  --device-batch-size 32 --grad-accum-steps 1 --max-seq-len 512

# 2. Stage 2 — SFT (LLM + projector full LR, DINOv2 @ 0.1x)
python -m scripts.vlm_sft --encoder dinov2 \
  --dinov2-weights $NANOCHAT_BASE_DIR/dinov2/dinov2_vitb14_pretrain.pth \
  --normalize imagenet --vit-lr-scale 0.1 --model-tag vlmsft_d12 \
  --max-steps 3000 --device-batch-size 32 --grad-accum-steps 1 --max-seq-len 512

# 3. Evaluate
python -m scripts.vlm_cli --image <img.jpg> --prompt "Describe this image." \
  --source vlm_sft --model-tag vlmsft_d12 --temperature 0.7 --max-tokens 60
